🚀 DB 마이그레이션 & Auto Increment 보정 표준 가이드

데이터 손실 Zero · 최고 이관 속도 보장 · 채번 충돌 방지 실무 가이드라인

📌 엔터프라이즈 데이터 이관 4단계 표준 절차

1. 사전 준비 STEP 1

  • 소스 DB 사전 VACUUM으로 WAL 및 Hint Bits 정리
  • 소스 데이터 건수(Count) 및 PK Checksum 메타데이터 기록
  • 타겟 DB에 PK/FK/인덱스를 뺀 '순수 정수 컬럼'으로 타겟 테이블 생성

2. 대량 데이터 적재 STEP 2

  • Parquet/Dump 파일을 타겟 DB에 병렬 적재
  • 적재 중 트랜잭션 로그/Undo 영역 모니터링
  • 제약조건이 제거된 상태이므로 병목 없이 최고 속도 이관 달성

3. 구조 완성 및 보정 STEP 3

  • 타겟 테이블에 PK, UNIQUE, Foreign Key 제약조건 추가
  • ID 컬럼에 IDENTITY / AUTO_INCREMENT 속성 부여
  • 시퀀스 번호를 현재 MAX(id) 값으로 반드시 동기화

4. 데이터 검증 STEP 4

  • 소스 vs 타겟 레코드 건수(Count Check) 비교
  • extractor.py 기준 PK Checksum / 해시값 검증
  • 신규 INSERT 테스트로 시퀀스 채번 정상 작동 확인
  • 테이블 통계정보(Analyze) 갱신으로 최적화 완료

🗄️ DB별 마이그레이션 스크립트 및 특수 유의사항

PostgreSQL IDENTITY / SERIAL

1. 이관 절차 스크립트

-- STEP 1: 타겟 테이블 DDL (순수 int4 생성) CREATE TABLE users (id INT4 NOT NULL, name VARCHAR(50)); -- STEP 2: [데이터 Bulk 적재 진행 (Parquet -> DB)] -- STEP 3: PK 추가, IDENTITY 적용 및 시퀀스 동기화 ALTER TABLE users ADD PRIMARY KEY (id); ALTER TABLE users ALTER COLUMN id ADD GENERATED BY DEFAULT AS IDENTITY; SELECT setval( pg_get_serial_sequence('users', 'id'), COALESCE(MAX(id), 1) ) FROM users; -- STEP 4: 데이터 검증 및 통계정보 갱신 SELECT COUNT(*) FROM users; ANALYZE users;
⚠️ PostgreSQL 이관 유의사항:
• `GENERATED ALWAYS` 대신 **`GENERATED BY DEFAULT`**를 써야 명시적 ID 주입 시 에러가 나지 않습니다.
• 대용량 이관 전 소스 DB에 `VACUUM`을 안 하면 덤프 중 WAL이 폭증하여 DB가 마비될 수 있습니다.
MySQL (InnoDB) AUTO_INCREMENT

1. 이관 절차 스크립트

-- STEP 1: 타겟 테이블 DDL (일반 INT 생성) CREATE TABLE users (id INT NOT NULL, name VARCHAR(50)); -- STEP 2: [데이터 Bulk 적재 진행] -- STEP 3: PK 추가, AUTO_INCREMENT 변경 및 시작값 설정 ALTER TABLE users ADD PRIMARY KEY (id); ALTER TABLE users MODIFY id INT AUTO_INCREMENT; -- MAX(id) 확인 후 그 다음 번호로 시작 설정 SET @max_id = (SELECT IFNULL(MAX(id), 0) + 1 FROM users); SET @sql = CONCAT('ALTER TABLE users AUTO_INCREMENT = ', @max_id); PREPARE stmt FROM @sql; EXECUTE stmt; DEALLOCATE PREPARE stmt; -- STEP 4: 데이터 검증 및 통계정보 갱신 SELECT COUNT(*) FROM users; ANALYZE TABLE users;
⚠️ MySQL 이관 유의사항:
• 대용량 적재 시 `UNIQUE_CHECKS=0;`, `FOREIGN_KEY_CHECKS=0;` 옵션을 잠시 끄면 적재 속도가 5배 이상 향상됩니다.
• `innodb_buffer_pool_size` 메모리 설정이 적절한지 미리 체크해야 합니다.
Oracle IDENTITY / SEQUENCE

1. 이관 절차 스크립트

-- STEP 1: 타겟 테이블 DDL CREATE TABLE users (id NUMBER(10) NOT NULL, name VARCHAR2(50)); -- STEP 2: [데이터 Bulk 적재 진행] -- STEP 3: PK 추가 및 IDENTITY 시퀀스 한 번에 맞춤 (12c+) ALTER TABLE users ADD CONSTRAINT pk_users PRIMARY KEY (id); ALTER TABLE users MODIFY id GENERATED BY DEFAULT AS IDENTITY (START WITH LIMIT VALUE); -- STEP 4: 데이터 검증 및 통계정보 갱신 SELECT COUNT(*) FROM users; EXEC DBMS_STATS.GATHER_TABLE_STATS(USER, 'USERS');
⚠️ Oracle 이관 유의사항:
• 대용량 적재 시 `NOLOGGING` 옵션 및 `APPEND` 힌트를 사용하면 Redo Log 생성을 최소화하여 이관 시간을 대폭 줄일 수 있습니다.
• `START WITH LIMIT VALUE` 구문을 활용하면 현재 테이블의 MAX 값으로 시퀀스가 자동 보정됩니다.
Microsoft SQL Server IDENTITY / RESEED

1. 이관 절차 스크립트

-- STEP 1: 이미 IDENTITY 컬럼으로 만든 테이블에 입력을 허용해야 할 때 SET IDENTITY_INSERT users ON; -- STEP 2: 데이터 Bulk Insert 진행 (명시적 ID 주입) INSERT INTO users (id, name) VALUES (1, '홍길동'); SET IDENTITY_INSERT users OFF; -- STEP 3: IDENTITY 시퀀스 현재 MAX(id)에 맞게 보정 DBCC CHECKIDENT ('users', RESEED); -- STEP 4: 데이터 검증 및 통계정보 갱신 SELECT COUNT(*) FROM users; UPDATE STATISTICS users;
⚠️ MS-SQL 이관 유의사항:
• `IDENTITY_INSERT ON`은 세션당 한 번에 **하나의 테이블에만** 적용 가능하므로 순차적으로 세션을 열어 처리해야 합니다.
• 적재 중 Log File(.ldf)이 꽉 차지 않도록 복구 모델(Recovery Model)을 잠시 `SIMPLE`로 변경하는 것이 좋습니다.

💡 가이드라인 요약

엔터프라이즈 마이그레이션의 완벽한 마무리는 STEP 4 검증(Count & Checksum & 채번 확인)입니다. 이관 작업 후 레코드 수 및 해시값 일치 여부를 파악하고, 테스트 INSERT를 통해 시퀀스가 보정되었음을 입증해야 서비스 오픈 시 예상치 못한 PK 에러를 100% 예방할 수 있습니다.
